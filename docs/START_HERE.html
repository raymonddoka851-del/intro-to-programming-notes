3. The 14-day plan (2–3 hours per day)

If your exam is about two weeks away, follow this. Each day has read → recall → code → questions.

1FundamentalsRead Note 01. Memorise the 8 development phases and 6+ characteristics of a good program. Write pseudocode and draw a flowchart for "largest of three numbers". Do Q1–Q10 in the question bank.
2C basics + compilationRead Note 02. Get a compiler working (see §7). Type and run hello.c, add_two.c, area_circle.c. Learn the compilation pipeline. Do Q11–Q20.
3Data types + number systemsRead Note 03. Practise 10 decimal↔binary conversions and 5 two's-complement conversions. Run data_types.c. Do Q21–Q30.
4OperatorsRead Note 04. Copy the precedence table from memory. Run operators.c. Do Q31–Q40.
5Control statementsRead Note 05. Write even/odd, largest of 3, grade program, calculator with switch. Do Q41–Q50.
6LoopsRead Note 06. Write sum 1..n, factorial, reverse digits, prime check, multiplication table, star triangle. Do Q51–Q60.
7Review + mini-testRe-do every wrong question from days 1–6. Do Sections A–F (Q1–Q60) of QUESTION_BANK.md under timed conditions.
8FunctionsRead Note 07 (first half). Write a function for max of two, factorial, prime check. Learn the four function categories. Do Q61–Q66.

4. How to study programming (even alone)

For every example program, use the P.A.C.E. method:

When you trace code in the exam, always draw a variable table:

LineisumOutput
i=110
sum+=i11
i++21

This prevents most lost marks.

5. Exam strategy (70% written paper)

Question types and how to answer

TypeWhat the examiner wantsTechnique
DefineA precise one- or two-sentence definitionLearn definitions word-for-word, then add an example
List / stateThe required number of pointsNumber your points; do not write a paragraph
DifferentiateA table with at least 3 clear differencesDraw the table even if not asked
ExplainMeaning + how it works + exampleUse the phrase "This means that… For example…"
Trace outputExact output, including new linesVariable table; watch / and %, prefix/postfix, loop bounds
Write a programCorrect, complete, readable codeIPO plan → declare → input → process → output → return 0;
DebugIdentify the error, explain it, correct itName the error type (syntax/runtime/logical)

Code-writing recipe (use every time)

Marks per minute

  • 70 marks in 120 minutes ≈ 1.7 minutes per mark.
  • Do the theory definitions first (fast marks), then tracing, then the long program.
  • If a program is 10 marks, spend at most ~15 minutes.
  • Never leave a program blank: declarations, main, input and output can earn part marks.

6. Must-know checklist

Tick each only when you can do it without notes.

Theory

  • ☐ Define program, programming, programming language, algorithm, pseudocode, flowchart
  • ☐ Classify programming languages (machine, assembly, high-level) with 2 advantages and 2 disadvantages each
  • ☐ Explain compiler vs interpreter (4 differences)
  • ☐ List 6 characteristics of a good program
  • ☐ List the 8 phases of program development in order
  • ☐ Explain syntax, runtime and logical errors with examples
  • ☐ Explain sequence, selection and repetition
  • ☐ Describe the 5 flowchart symbols and 5 algorithm representations
  • ☐ Describe the compilation pipeline (preprocessor, compiler, assembler, linker, loader)

C language

  • ☐ Write the structure of a C program from memory
  • ☐ List 5 header files and what they provide
  • ☐ State the rules for identifiers and list 10 keywords
  • ☐ Explain #define vs const
  • ☐ Convert decimal ↔ binary ↔ octal ↔ hex
  • ☐ Explain signed vs unsigned, 2's complement, range of 8-bit numbers
  • ☐ Explain int, float, double, char (size, format specifier, example)
  • ☐ State key ASCII codes ('A', 'a', '0', space, newline)
  • ☐ Explain implicit conversion and casting
  • ☐ Use all operator types; state precedence and associativity
  • ☐ Evaluate prefix vs postfix expressions
  • ☐ Write if, if-else, else-if, nested if, switch
  • ☐ Write while, do-while, for, nested loops
  • ☐ Use break, continue, goto correctly
  • ☐ Define function, prototype, definition, call, return
  • ☐ Explain actual vs formal parameters
  • ☐ Explain call by value vs call by reference
  • ☐ Explain local vs global vs static scope
  • ☐ Write a recursive function with a base case
  • ☐ Declare/initialise 1D and 2D arrays
  • ☐ Search (linear/binary) and sort (bubble) an array
  • ☐ Explain how strings are stored; use strlen, strcpy, strcat, strcmp
  • ☐ Declare pointers, use & and *, do pointer arithmetic
  • ☐ Explain the link between arrays and pointers
  • ☐ Define and use a struct, array of structs, typedef, ->
  • ☐ Explain struct vs union
  • ☐ Open, write, read and close a text file
  • ☐ Format output with width and precision; design a simple report

7. Running C code (already set up for you)

A C compiler (GCC) is already installed on this computer. You do not need to install anything.

The easy way: double-click RUN_CODE.bat in this folder, type a program name (for example hello.c), and press Enter. You can also drag any .c file from the code/ folder onto RUN_CODE.bat.

Full instructions, terminal commands and fixes for common compiler errors are in SETUP_AND_RUN.md.

If the local compiler ever fails, use the online compiler: <https://www.onlinegdb.com/online_c_compiler> — paste the code and press Run.

Do not spend study time installing IDEs. A compiler plus RUN_CODE.bat is enough for this exam.

7b. Reading the notes (nicely formatted)

The .md files are Markdown. If you double-click one, Word or Notepad opens it as raw text and you see #, ** and | symbols — that is normal, but it is not meant to be read that way.

Double-click OPEN_NOTES.bat to read everything the way it is supposed to look: formatted headings, coloured tables, highlighted C code, a sidebar, search, and a dark mode. Every page can be saved as a PDF with Ctrl+P.

The browser version is generated from the same .md files, so the two always match.

8. A note about what is published

This folder is also a public GitHub repository. Only the revision material is uploaded: notes, programs, practice questions and the formatted HTML site.

Anything personal stays on your computer and is never committed — exam slips, screenshots, student emails and two-factor backup codes. .gitignore blocks the common accidents (build outputs, students.txt written by file_records.c).
