Section A — Programming fundamentals

Q1. (a) Program: a finite set of sequenced instructions that tells a computer how to perform a task. (b) Programming: the process of designing, writing, testing and maintaining those instructions. (c) Programming language: a formal language with syntax and semantics used to write instructions, e.g. C, Python, Java.

Q2. Low-level languages (machine and assembly):

  • Advantages: fast execution; efficient use of memory; no translator needed for machine code; direct control of hardware.
  • Disadvantages: machine-dependent; difficult to learn/write/read; error-prone; bulky; time-consuming to develop.

High-level languages (C, Python, Java):

  • Advantages: machine-independent/portable; easy to learn and write; readable; easier to debug and maintain.
  • Disadvantages: need translation (compiler/interpreter); slower than low-level; less memory-efficient; cannot access hardware directly.

Q4.

  1. Compiler translates the whole program at once; interpreter translates one statement at a time.
  2. Compiler produces object code; interpreter produces no object code.
  3. Compiler reports errors after scanning the whole program; interpreter stops at the first error.
  4. Compiled programs generally execute faster; interpreted programs execute slower but are easier to debug.
  5. C/C++ use compilers; Python/Ruby commonly use interpreters.

Q5.

  1. Problem definition/analysis — understand the problem, inputs, outputs and requirements.
  2. Algorithm selection/development — write the steps to solve it.
  3. Program design — represent the logic using flowcharts, pseudocode, IPO/HIPO.
  4. Coding — write the program in a programming language.
  5. Compilation — translate source code to object code; remove syntax errors.
  6. Testing, running and debugging — run with test data and fix errors.
  7. Documentation — record how the program works and how to use it.
  8. Maintenance — correct, modify and improve the program after release.

Q6. Any six with a sentence each:

  • Correctness/reliability — does what it is supposed to do.
  • Portability — runs on different machines with little/no change.
  • Efficiency — uses reasonable time and memory.
  • Simplicity/readability — easy to read and understand.
  • Maintainability — easy to modify and fix.
  • Robustness — handles invalid input without crashing.
  • Cost-effectiveness — benefits outweigh development cost.
  • Documentation — well explained for users and maintainers.

Q7. (a) An algorithm is a finite, ordered, unambiguous set of steps that solves a problem. (b) Features: input, output, definiteness (clear steps), finiteness (must terminate), effectiveness (each step is simple enough to perform), and it should produce a unique solution.

Q8. Algorithm:

  1. Start.
  2. Read A, B, C.
  3. If A ≥ B and A ≥ C, then Largest = A.
  4. Else if B ≥ A and B ≥ C, then Largest = B.
  5. Else Largest = C.
  6. Print Largest.
  7. Stop.

Pseudocode:

BEGIN
  INPUT A, B, C
  IF A >= B AND A >= C THEN
      Largest = A
  ELSE IF B >= A AND B >= C THEN
      Largest = B
  ELSE
      Largest = C
  END IF
  PRINT Largest
END

Q10.

  • Syntax error: breaks the grammar of C; detected by the compiler; the program will not compile. Example: printf("Hi") missing ;.
  • Runtime error: occurs while the program runs, after successful compilation. Example: division by zero a / 0.
  • Logical error: the program compiles and runs but gives the wrong result. Example: using average = sum + n instead of sum / n.

Parts: documentation/comments, preprocessor directives, global declarations, main function, declarations, executable statements, return.

Q12. A header file contains declarations of functions, macros and types used by the program; it is included with #include.

  • <stdio.h> — input/output (printf, scanf, fopen).
  • <stdlib.h> — general utilities (malloc, free, exit, atoi).
  • <math.h> — mathematical functions (sqrt, pow, sin).
  • <string.h> — string functions (strlen, strcpy, strcmp).
  • <ctype.h> — character tests (isalpha, isdigit, toupper).
  • <conio.h> — console input/output (non-standard; getch).

Q13. Rules:

  • Must begin with a letter or underscore.
  • May contain only letters, digits and underscores.
  • No spaces or special symbols.
  • Cannot be a keyword.
  • Case-sensitive; meaningful names recommended.

Valid: total, _count, Sum. Invalid: 2ndNumber (starts with a digit), student-name (hyphen), float (keyword).

Q14. Keywords are reserved words with a fixed meaning to the compiler, e.g. int, float, char, if, else, for, while, return, void, switch. They cannot be used as identifiers because the compiler would confuse the user name with its own reserved instruction.

Q16.

  • /* ... */ — block comment, can span lines.
  • // ... — single-line comment (C99 onwards).

Reasons: document the program; explain difficult logic; record author/date/version; temporarily disable code. Comments cannot be nested — the first */ closes the comment.

Q17.

  1. Preprocessor — handles #include, #define, conditional compilation; produces expanded source code.
  2. Compiler — checks syntax and translates the expanded source into assembly language.
  3. Assembler — translates assembly into machine/object code (.o/.obj).
  4. Linker — combines the object code with library code and other object files to produce an executable.
  5. Loader — loads the executable from secondary storage into memory and starts execution.

Q18.

  • Source code: human-readable program written in a high-level language, e.g. program.c.
  • Object code: machine code produced by the compiler, e.g. program.o; not yet executable because library functions are missing.
  • Executable: fully linked file, e.g. program.exe, that the operating system can run.

Q19. The linker combines object files and library functions (e.g. printf) into one executable program and resolves references between them. Without it, the object code would lack the library code needed to run.

Q20. Two errors:

  1. Syntax error: the printf statement is missing its semicolon (;). The program will not compile.
  2. Runtime error (after fixing the semicolon): a / b divides by zero because b = 0, causing undefined behaviour/a crash.

Section C — Data types and number systems

Q21. A bit is one binary digit (0 or 1). A byte is 8 bits. A nibble is 4 bits. A word is the natural unit a CPU processes at once (often 16, 32 or 64 bits). Values: 4 bits → 2⁴ = 16; 8 bits → 2⁸ = 256; n bits → 2ⁿ.

Q22.

  • 13 = 1101
  • 45 = 101101
  • 100 = 1100100
  • 255 = 11111111

Q23.

  • 1011 = 8 + 2 + 1 = 11
  • 110010 = 32 + 16 + 2 = 50
  • 11111111 = 128+64+32+16+8+4+2+1 = 255

Q24. (a) 60 ÷ 8 = 7 remainder 4, 7 ÷ 8 = 0 remainder 7 → 074₈. (b) 60 = 3×16 + 12 → 0x3C. (c) 101011 → group 0010 1011 → 0x2B. (d) 3F = 3×16 + 15 = 63.

Q25. Signed integers can be positive, negative or zero and use one bit (usually the leftmost) for the sign. Unsigned integers are only zero or positive, so all bits represent magnitude.

  • 8-bit unsigned: 0 to 255.
  • 8-bit signed (two's complement): −128 to +127.
  • 16-bit signed: −32,768 to +32,767.

Q26. (a) −12: 12 = 00001100 → invert 11110011 → +1 = 11110100 (0xF4). −25: 25 = 00011001 → invert 11100110 → +1 = 11100111 (0xE7).

(b) Two's complement has only one representation of zero, makes addition and subtraction use the same hardware, and handles overflow simply. Sign-and-magnitude has two zeros (+0 and −0) and needs separate subtraction circuitry.

Q28. 'A' = 65, 'a' = 97, '0' = 48, space = 32, '\n' = 10, '\0' = 0. A character code is the numeric value used internally to represent a character (C uses ASCII on most systems).

Q29.

  • Implicit conversion: automatic conversion by the compiler when types are mixed, e.g. int to float in 3 + 2.5.
  • Explicit casting: the programmer forces a conversion with (type), e.g. (float)7 / 2.

(a) 7 / 2 = 3 (integer division). (b) (float)7 / 2 = 3.5. (c) (int)7.9 = 7 (fraction discarded). (d) 'A' + 1 = 65 + 1 = 66 (which is 'B').

Q45.

{
    case constant1: statements; break;
    case constant2: statements; break;

Rules:

  • The expression must be an integer or character type (not float or a string).

Section G — Functions and recursion

Q61. A function is a named block of code that performs one specific task and can be called whenever needed. Advantages: reusability; readability; easier testing/debugging; easier maintenance; avoids repetition; supports divide-and-conquer and teamwork.

Q62.

  • Prototype: declaration of the function's name, return type and parameter types, ending with ;, e.g. int max(int a, int b);.
  • Definition: the actual body with the code.
  • Call: using the function, e.g. m = max(3, 7);. 
    #include <stdio.h>
int max(int a, int b);          /* prototype */

int main(void)
{
    int x = 3, y = 7;
    printf("Max = %d\n", max(x, y));   /* call */
    return 0;
}

int max(int a, int b)           /* definition */
{
    return (a > b) ? a : b;
}

Q63. Actual parameters (arguments) are the values/variables supplied in the function call, e.g. x and y in max(x, y). Formal parameters are the variables declared in the function definition that receive those values, e.g. a and b in int max(int a, int b). C passes them by value.

Q64. Four categories:

  1. No arguments, no return value: void greet(void) { printf("Hi"); }
  2. No arguments, with return value: int readNumber(void) { int n; scanf("%d",&n); return n; }
  3. With arguments, no return value: void printSum(int a, int b) { printf("%d", a+b); }
  4. With arguments and return value: int add(int a, int b) { return a+b; }

Q65. Call by value passes a copy of the argument; changes inside the function do not affect the caller. Call by reference passes the address; changes through the pointer do affect the caller. C uses call by value, but pointers simulate call by reference.

void swap(int *a, int *b)
{
    int temp = *a;
    *a = *b;
    *b = temp;
}
/* call: swap(&x, &y); */

Q66.

  • Local: declared inside a function/block; accessible only there; lifetime = while the block runs; no default value (garbage unless initialised).
  • Global: declared outside all functions; accessible throughout the file/program; lifetime = whole program; default value 0.
  • Static local: declared with static inside a function; accessible only there; lifetime = whole program; default value 0; keeps its value between calls.

Q67. Recursion is when a function calls itself to solve a smaller version of the same problem. Two parts:

  1. Base case — the stopping condition.
  2. Recursive case — the function calls itself with a smaller input. 
    long long fact(int n)
{
    if (n <= 1) return 1;       /* base case */
    return n * fact(n - 1);     /* recursive case */
}

Q68. factorial(4) → 4 * factorial(3) → 4 * 3 * factorial(2) → 4 * 3 * 2 * factorial(1) → 4 * 3 * 2 * 1 = 24. Calls: fact(4), fact(3), fact(2), fact(1); then returns 1, 2, 6, 24.

Q69.

int fib(int n)
{
    if (n <= 1) return n;       /* base: fib(0)=0, fib(1)=1 */
    return fib(n - 1) + fib(n - 2);
}

It is inefficient because the same subproblems are recalculated many times (exponential time, O(2ⁿ)). It can be improved with memoisation or an iterative loop.

Q70.

int sumDigits(int n)
{
    if (n == 0) return 0;
    return (n % 10) + sumDigits(n / 10);
}
/* sumDigits(1234) = 4 + 3 + 2 + 1 = 10 */

Q74. Linear search checks each element from the beginning until the target is found or the array ends. It works on unsorted arrays; time is O(n).

#include <stdio.h>
int main(void)
{
    int a[100], n, i, key, found = -1;
    printf("Enter n: "); scanf("%d", &n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);
    printf("Enter value to search: "); scanf("%d", &key);

    for (i = 0; i < n; i++) {
        if (a[i] == key) { found = i; break; }
    }
    if (found != -1) printf("Found at index %d\n", found);
    else             printf("Not found\n");
    return 0;
}

Q75. Bubble sort repeatedly compares adjacent pairs and swaps them if they are in the wrong order. After each pass, the largest remaining value "bubbles" to the end.

#include <stdio.h>
int main(void)
{
    int a[100], n, i, j, temp;
    printf("Enter n: "); scanf("%d", &n);
    for (i = 0; i < n; i++) scanf("%d", &a[i]);

    for (i = 0; i < n - 1; i++) {
        for (j = 0; j < n - 1 - i; j++) {
            if (a[j] > a[j + 1]) {
                temp = a[j];
                a[j] = a[j + 1];
                a[j + 1] = temp;
            }
        }
    }
    printf("Sorted: ");
    for (i = 0; i < n; i++) printf("%d ", a[i]);
    return 0;
}

Trace for {5, 1, 4, 2, 8}:

  • Pass 1: {1,5,4,2,8} → {1,4,5,2,8} → {1,4,2,5,8} → {1,4,2,5,8}
  • Pass 2: {1,4,2,5,8} → {1,2,4,5,8}
  • Pass 3: no swaps → sorted {1, 2, 4, 5, 8}.

{

Section I — Pointers

Q81. A pointer is a variable that stores the memory address of another variable.

int x = 10;
int *p = &x;    /* p holds the address of x */

& is the address-of operator (&x gives x's address). * is the dereference/indirection operator (*p gives the value at the address, 10).

Q82. Memory:

x: [ 10 ]  at address, say, 1000
p: [1000]  → points to x

Output: 10 10. *p = 10 changes x itself to 10.

Q83. Pointer arithmetic moves in units of the pointed-to type, not bytes. If int *p = &a[0], then p + 2 points to a[2]. On a machine where int is 4 bytes, p + 1 moves 4 bytes (one integer) forward.

Q84. An array name acts like a pointer to its first element. For int a[5], a is equivalent to &a[0], and a[i] is defined as *(a + i). So a[2] and *(a + 2) are the same value, and &a[2] equals a + 2. Arrays are not pointers, but they decay to pointers when passed to functions.

Q85.

#include <stdio.h>
void swap(int *a, int *b)
{
    int temp = *a;
    *a = *b;
    *b = temp;
}
int main(void)
{
    int x = 3, y = 8;
    swap(&x, &y);
    printf("x = %d, y = %d\n", x, y);   /* x = 8, y = 3 */
    return 0;
}

Call by value alone passes copies, so swapping the copies leaves the originals unchanged. Passing addresses lets the function modify the original variables.

  • calloc(n, size) allocates n × size bytes and initialises them to zero.

  • free(ptr) releases the memory.

Q95. Four common mistakes:

  1. Missing & in scanf("%d", x); → use scanf("%d", &x); (arrays are the exception).
  2. Using %f for a double in scanf → use %lf.
  3. %c reading leftover whitespace/newline → write scanf(" %c", &ch); with a leading space.
  4. No width limit for %s causing buffer overflow → use scanf("%49s", name); for a 50-byte array.
  5. Also: wrong specifier/type mismatch, and forgetting that scanf stops at whitespace.
